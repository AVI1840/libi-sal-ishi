## 2. סיכום מצב

### מה עובד באמת (Production-grade logic)
- מנוע קליטה: 6 שאלות → ICF + פרסונה + דגלי סיכון
- מנוע המלצות: 4-factor scoring + persona boost + safety filter
- מנוע סבסוד: 5 עולמות תוכן × טיירים + 2 בוסטרים + תקרה
- CRM: 6 סוגי פעולות, מיון לפי דחיפות
- 10 כללי החלטה מוגדרים ומתועדים

### מה מדומה (Mock / Demo-only)
- 75 לקוחות — generated אקראית, לא מ-DB
- 18 שירותים — hardcoded, לא מ-vendor registry
- ארנק — לוגיקה בלבד, אין persistence
- הזמנות — mock data, אין אישור ספק אמיתי
- KPIs — ערכים סטטיים, לא מחושבים מנתונים
- AI שיחתי — agent קיים, LLM לא מחובר

### מה חסר (לא קיים כלל)
- אימות קליני של ICF
- Feedback loop (שאלון אחרי שירות + למידה)
- Escalation אוטומטי מלא (backend)
- תשלום אמיתי לספקים
- Multi-tenancy (הפרדה בין רשויות)
- WhatsApp integration
- Health monitoring אמיתי

### מה חוסם פיילוט
1. **הכרעת מודל תקציבי** — מי משלם, איך הכסף זורם
2. **הכרעת ספקים** — מי מאשר, מחירון תקרה, אונבורדינג
3. **הכרעת סבסוד** — אימות מול מדיניות רשמית (רמות 1-3 לפחות)
4. **הכרעת תפקיד מתאמת** — סמכויות, יחס שירות, אחריות
5. **הכרעת הערכה תפקודית** — רמת אימות נדרשת לפני המלצות

## 3. פערים נרטיביים שתוקנו

| פער | מה היה | מה תוקן |
|-----|--------|---------|
| "MVP" vs "Demo" | מסמכים שונים השתמשו במונחים לסירוגין | הוגדר: Demo = מצב נוכחי, MVP = תוצר מינימלי לפיילוט |
| רמות סיעוד | חלק מהמסמכים כתבו 1-6, חלק 1-3 | הובהר: פיילוט = רמות 1-3 בלבד, 4-6 = אומדן לשלב 2 |
| "75 לקוחות" | הוצג כנתון אמיתי | סומן כ-mock generated data |
| "מערכת עובדת" | חומרי דמו הציגו כמערכת מלאה | הובהר: לוגיקה עובדת, שכבת נתונים = mock |
| מספר הכרעות | מסמכים שונים ציינו 5-7-10 הכרעות | יושר ל-5 הכרעות קריטיות לפיילוט |
