# סל אישי — מפת מוכנות MVP

> מה מוכן להצגה, מה מוכן לפיילוט, מה חייב הכרעה, מה חייב פיתוח

---

## מוכן להצגה (דמו אסטרטגי)

| רכיב | מצב | הערה |
|------|------|------|
| ממשק אזרח — סל שירותים, ארנק, המלצות | עובד | נתוני דמו, לוגיקה אמיתית |
| מנוע המלצות — 4 פקטורים + פרסונה | עובד | scoring + safety filter + persona boost |
| מנוע סבסוד דינמי — 5 עולמות תוכן | עובד | tier + boosters + cap |
| CRM פרואקטיבי — פעולות חכמות למלווה | עובד | 6 סוגי פעולות, הסלמה 72 שעות |
| תרחיש שרה כהן — E2E בכל הממשקים | עובד | קליטה → המלצה → הזמנה → מעקב → KPI |
| פורטל ספקים — הזמנות, שירותים, תשלומים | עובד | נתוני דמו |
| מערכת מלווה — 75 לקוחות, פעולות, KPI | עובד | data layer מלא |
| שער כניסה — חדר הדגמה מקצועי | עובד | 4 כרטיסי כניסה + שקיפות דמו |

## מוכן לפיילוט (עם התאמות)

| רכיב | מצב | מה חסר |
|------|------|--------|
| אשף קליטה — 6 שאלות | API קיים | חיבור frontend → backend |
| חישוב פרופיל ICF + פרסונה | לוגיקה קיימת | persistence ל-DB |
| הקצאת ארנק לפי רמת סיעוד | לוגיקה קיימת | חיבור לביטוח לאומי (ידני) |
| אימות פרסונה ע"י מלווה | UI + API קיימים | audit trail |
| אימות ICF ע"י מלווה | UI + API קיימים | workflow approval |
| משוב אחרי שירות | UI + API קיימים | aggregation + learning |
| הסלמה אוטומטית CRM | לוגיקה קיימת | notifications (email/SMS) |

## חייב הכרעה (מדיניות / תקציב)

| נושא | שאלה | מי מחליט |
|------|-------|----------|
| רמות סיעוד 4-6 | המרת שעות ליחידות — אומדן או מדיניות? | ביטוח לאומי |
| מודל התקשרויות | 3 צירים: מפעיל מערכת, מפעיל שטח, ספקים | אוצר + בט"ל |
| תקרות מחיר | מחירון יחידות לפי עולם תוכן | ועדת מחירים |
| multi-tenancy | הפרדה בין אתרים — authority_id | ארכיטקטורה |
| WhatsApp | ערוץ תקשורת לאזרחים — Business API | רכש + פרטיות |
| אבטחת מידע | PII, הצפנה, GDPR/תקנות פרטיות | CISO |

## חייב פיתוח לפני שטח

| רכיב | מורכבות | זמן הערכה |
|------|---------|-----------|
| PostgreSQL — persistence מלא | בינונית | 2 שבועות |
| JWT auth + RBAC ברמת רשות | בינונית | 1 שבוע |
| חיבור frontend ↔ backend E2E | בינונית | 2 שבועות |
| אונבורדינג ספקים אמיתיים | נמוכה | 1 שבוע |
| notifications (email/SMS/push) | בינונית | 1 שבוע |
| audit trail מלא | נמוכה | 3 ימים |
| ייצוא דוחות PDF | נמוכה | 3 ימים |
| אבטחת מידע + הצפנת PII | גבוהה | 2 שבועות |
| load testing + monitoring | בינונית | 1 שבוע |

## ציר זמן מוצע

```
חודש 1-2: חיבור DB + auth + E2E אחד מלא
חודש 2-3: אונבורדינג ספקים + notifications + audit
חודש 3-4: אבטחה + multi-tenancy + load testing
חודש 4:   פיילוט מבוקר — אתר ראשון (פסגת זאב)
חודש 5-6: הרחבה ל-3 אתרים נוספים
חודש 7-12: הרחבה ל-6-8 אתרים + מדידה + התאמות
```
